# Provider Authority Matrix (Security Header Ownership)

This template records which provider owns each HTTP security header for
`mmerlone.dev.br`. It is intentionally separate from `README.md` and the
`PLAN-*.md` files so it can be filled in and updated independently.

Only **Marcio Merlone** can inspect provider dashboards, change provider
settings, and attest that this matrix is complete. An agent may create the
template and record user-supplied evidence, but may not claim a setting is
enabled until it has been observed in a live response.

## Cloudflare checklist

- [ ] Confirm Cloudflare is the authoritative DNS provider for `mmerlone.dev.br`
      on the Free zone plan.
- [ ] Verify all DNS records are set to **DNS only** (grey-clouded), so Cloudflare
      does not proxy or cache site content; Vercel owns the edge, TLS, HSTS, WAF,
      and caching.
- [ ] Confirm DNSSEC is configured for the zone and records the expected DS
      fingerprint.
- [ ] Review CAA records authorize only the intended certificate providers.
- [ ] Since Cloudflare is DNS-only here, no Cloudflare edge caching or Transform
      Rules apply, so `Vary: Accept` is owned by Vercel and the HTML/Markdown
      variants are never collapsed by Cloudflare.

## Vercel checklist

- [ ] Canonical custom domain assigned to the intended project; automatic
      HTTPS enabled.
- [ ] Project firewall/WAF rules and environment-specific deployment behavior
      reviewed.
- [ ] Direct-origin and preview responses receive the application-owned
      headers from `next.config.ts` and do **not** add HSTS.
- [ ] Preview and production deployments share the same application security
      policy, or intentional differences are documented.

## GitHub checklist

- [ ] GitHub does not serve this site and is not treated as an HTTP-header
      provider.
- [ ] Actions, Dependabot security alerts/version updates, and branch
      protection for `main` enabled.
- [ ] Repository quality checks required before merge.
- [ ] Minimal workflow permissions (`contents: read` unless a deployment step
      requires more); no provider credentials in workflow files or logs.

## Notes

- The application-owned headers are generated by
  [`buildSecurityHeaders`](src/lib/buildSecurityHeaders.ts) and emitted through
  `next.config.ts` async `headers()`. They apply to direct Vercel, preview,
  and production responses.
- HSTS is **never** emitted by repository code; Vercel owns it.
- Record observed behavior and any deviation here; never emit duplicate HSTS or
  CSP headers.
